## Importing the Framework

You can import the FPI Framework into your Maven project using one of the following methods:

### Option 1: As Parent POM

Add the FPI Framework Parent POM to your project's `pom.xml`:

```xml
<parent>
  <!-- FPI Framework Parent POM -->
  <groupId>com.abavilla</groupId>
  <artifactId>fpi-framework-pom</artifactId>
  <version>1.1.1</version> <!-- Replace with the latest version -->
</parent>

<!-- Dependencies defined in the parent POM, 
     so no need to add fpi-framework-core explicitly. -->
```

### Option 2: As Bill of Materials (BOM)

Import the FPI Framework BOM in your `dependencyManagement` section and then add `fpi-framework-core` as a dependency:

```xml
<dependencyManagement>
  <dependencies>
    <!-- FPI Framework BOM -->
    <dependency>
      <groupId>com.abavilla</groupId>
      <artifactId>fpi-framework-bom</artifactId>
      <version>1.1.1</version> <!-- Replace with the latest version -->
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

<dependencies>
  <!-- FPI Framework Core dependency -->
  <dependency>
    <groupId>com.abavilla</groupId>
    <artifactId>fpi-framework-core</artifactId>
  </dependency>
  <!-- Add other FPI Framework modules as needed -->
</dependencies>
```

## Sample Usage

Here's a brief example demonstrating how to use the core components of the FPI Framework to create a simple `Student` entity and its related DTO, repository, mapper, service, and REST controller.

### Entity

Define your entity by extending `AbsMongoItem` (for MongoDB).

```java
package com.example.model;

import com.abavilla.fpi.fw.entity.AbsMongoItem;
import lombok.Data;
import lombok.EqualsAndHashCode;
import lombok.NoArgsConstructor;
import org.bson.codecs.pojo.annotations.BsonDiscriminator;
import io.quarkus.mongodb.panache.common.MongoEntity;

@Data
@EqualsAndHashCode(callSuper = true)
@NoArgsConstructor
@BsonDiscriminator // Optional: for polymorphism if using subclasses
@MongoEntity(collection="students") // Specifies the MongoDB collection name
public class Student extends AbsMongoItem {
  /** Student name */
  private String name;
  /** Student home address */
  private String address;
  /** Student gender */
  private String gender;

  // Getters and setters are automatically generated by Lombok
  // during compile time, no need to specify them explicitly.
}
```

### DTO (Data Transfer Object)

Create a DTO by extending `AbsDto`.

```java
package com.example.dto;

import com.abavilla.fpi.fw.dto.AbsDto;
import lombok.Data;
import lombok.EqualsAndHashCode;
import lombok.NoArgsConstructor;

@Data
@EqualsAndHashCode(callSuper = true)
@NoArgsConstructor
public class StudentDto extends AbsDto {
  /** Student name */
  private String name;
  /** Student gender */
  private String gender;
  
  // Getters and setters are automatically generated by Lombok.
}
```

### Repository

Create a repository by extending `AbsMongoRepo`.

```java
package com.example.repository;

import com.abavilla.fpi.fw.repo.AbsMongoRepo;
import com.example.model.Student;
import jakarta.enterprise.context.ApplicationScoped;

@ApplicationScoped
public class StudentRepo extends AbsMongoRepo<Student> {
  // No need to specify a body, as AbsMongoRepo extends PanacheMongoRepositoryBase
  // and already implements basic CRUD (Create, Read, Update, Delete) methods.
  // Custom query methods can be added here if needed.
}
```

### Mapper (DTO to Entity)

Define a MapStruct mapper interface that extends `IDtoToEntityMapper`.

```java
package com.example.mapper;

import com.abavilla.fpi.fw.mapper.IDtoToEntityMapper;
import com.example.dto.StudentDto;
import com.example.model.Student;
import org.mapstruct.Mapper;
import org.mapstruct.MappingConstants;
import jakarta.enterprise.context.ApplicationScoped; // Or use another injection strategy if preferred
import org.mapstruct.InjectionStrategy;


@Mapper(
    componentModel = MappingConstants.ComponentModel.CDI, // For CDI integration (e.g., Quarkus)
    injectionStrategy = InjectionStrategy.CONSTRUCTOR // Recommended injection strategy
)
public interface StudentMapper extends IDtoToEntityMapper<StudentDto, Student> {
  // MapStruct will generate the implementation for mapping methods like:
  // StudentDto mapToDto(Student entity);
  // Student mapToEntity(StudentDto dto);
  // List<StudentDto> mapToDtoList(List<Student> entities);
  // List<Student> mapToEntityList(List<StudentDto> dtos);
  // No explicit body is needed as IDtoToEntityMapper specifies commonly used mapping methods.
}
```

### Service Layer

Implement the service layer by extending `AbsSvc` (or `AbsRepoSvc` if you need a customized repository).

```java
package com.example.service;

import com.abavilla.fpi.fw.service.AbsSvc;
import com.example.dto.StudentDto;
import com.example.model.Student;
import com.example.mapper.StudentMapper; // Ensure this import is correct
import jakarta.enterprise.context.ApplicationScoped;
import jakarta.inject.Inject;

@ApplicationScoped
public class StudentSvc extends AbsSvc<StudentDto, Student> {
  
  private final StudentMapper mapper; // Prefer final for constructor injection

  @Inject // Constructor injection is generally preferred
  public StudentSvc(StudentMapper mapper) {
    this.mapper = mapper;
  }
  
  // Built-in asynchronous (Mutiny) CRUD methods are available.
  // You only need to specify the mapping methods to convert
  // between DTOs and entities.
  
  @Override
  public StudentDto mapToDto(Student entity) {
    return mapper.toDto(entity); // Corrected to use toDto from IDtoToEntityMapper
  }

  @Override
  public Student mapToEntity(StudentDto dto) {
    return mapper.toEntity(dto); // Corrected to use toEntity from IDtoToEntityMapper
  }
}
```

### REST Controller

Create a REST controller by extending `AbsResource`.

```java
package com.example.controller;

import com.abavilla.fpi.fw.controller.AbsResource;
import com.example.dto.StudentDto;
import com.example.model.Student;
import com.example.service.StudentSvc; // Ensure this import is correct
import jakarta.ws.rs.Path;
import jakarta.enterprise.context.ApplicationScoped; // Added for clarity

@Path("/api/students") // Example path
@ApplicationScoped     // Standard scope for Quarkus REST resources
public class StudentResource extends AbsResource<StudentDto, Student, StudentSvc> {
  // Built-in asynchronous (Mutiny) CRUD methods for GET, POST,
  // PATCH, DELETE are implemented by default from AbsResource.
  // You may customize these or add your own methods for specific requirements.
  // For example, to inject the service (if not handled by a base class constructor not shown):
  // 
  // @Inject
  // public StudentResource(StudentSvc service) {
  //     super(service); // Assuming AbsResource has such a constructor
  // }
  // 
  // Or if the service is injected directly by AbsResource, no explicit constructor is needed here.
  // Refer to the specific implementation of AbsResource for injection details.
}
```

## Core Components

This framework provides a set of core components to accelerate REST API development. These components include base classes and interfaces for controllers, DTOs, entities, mappers, repositories, and services.

### Controllers

The `com.abavilla.fpi.fw.controller` package contains base classes and interfaces for creating REST controllers:

*   **`AbsBaseResource`**: An abstract class providing common functionalities for REST resources.
*   **`AbsReadOnlyResource`**: An abstract class for resources that only provide read-only operations.
*   **`AbsResource`**: An abstract class that extends `AbsBaseResource` and implements `ICRUDResource`, providing default implementations for CRUD operations.
*   **`ICRUDResource`**: An interface defining the contract for CRUD operations (Create, Read, Update, Delete).
*   **`IReadOnlyResource`**: An interface defining the contract for read-only operations.
*   **`IResource`**: A marker interface for REST resources.

**Example:** Refer to the `StudentResource` example in the Sample Usage section.

### Data Transfer Objects (DTOs)

The `com.abavilla.fpi.fw.dto` package provides base classes and interfaces for DTOs:

*   **`AbsDto`**: An abstract base class for DTOs. It includes common fields like `id`, `createdAt`, `updatedAt`, and `version`.
*   **`AbsFieldDto`**: An abstract class for DTOs that represent a field or a sub-document.
*   **`IDto`**: A marker interface for DTOs.

**Example:** Refer to the `StudentDto` example in the Sample Usage section.

### Entities

The `com.abavilla.fpi.fw.entity` package provides base classes and interfaces for entities:

*   **`AbsItem`**: An abstract base class for entities. It includes common fields like `id`, `createdAt`, `updatedAt`, and `version`.
*   **`IField`**: An interface for fields or sub-documents within an entity.
*   **`IItem`**: A marker interface for entities.
*   **`AbsMongoItem`**: An abstract class that extends `AbsItem` for MongoDB entities. It uses `@MongoEntity` for collection mapping.
*   **`AbsMongoField`**: An abstract class for fields or sub-documents within a MongoDB entity.

**Example:** Refer to the `Student` entity example in the Sample Usage section.

### Mappers

The `com.abavilla.fpi.fw.mapper` package provides interfaces for mapping between DTOs and entities:

*   **`IDtoToEntityMapper<D extends IDto, E extends IItem>`**: An interface for mappers that convert DTOs to entities and vice-versa. It typically uses MapStruct for implementation. Its methods are `toDto` and `toEntity`.
*   **`IMapper`**: A marker interface for mappers.
*   **`IMongoItemMapper`**: An interface for mappers specific to MongoDB items.

**Example:** Refer to the `StudentMapper` example in the Sample Usage section.

### Repositories

The `com.abavilla.fpi.fw.repo` package provides base classes and interfaces for repositories:

*   **`AbsMongoRepo<E extends AbsMongoItem>`**: An abstract class for MongoDB repositories. It extends `PanacheMongoRepositoryBase` and provides common database operations.
*   **`IMongoRepo`**: A marker interface for MongoDB repositories.

**Example:** Refer to the `StudentRepo` example in the Sample Usage section.

### Services

The `com.abavilla.fpi.fw.service` package provides base classes and interfaces for services:

*   **`AbsSvc<D extends IDto, E extends AbsItem>`**: An abstract class for services that handle business logic. It requires a mapper to convert between DTOs and entities.
*   **`AbsRepoSvc<D extends IDto, E extends AbsItem, R extends IMongoRepo<E>>`**: An abstract class that extends `AbsSvc` and includes a repository for database operations.
*   **`IProviderSvc`**: An interface for services that provide data from external sources.
*   **`ISvc`**: A marker interface for services.

**Example:** Refer to the `StudentSvc` example in the Sample Usage section.
